1. Introduction

1.1 What is This Software?

The Serial Data Logger and Plotter is a professional-grade data acquisition system for fatigue testing equipment. It acquires real-time data via serial communication, logs it to disk, and displays it on three synchronized plots.

Version 2.2 adds:

  • NEW Automatic COM port detection
  • NEW Port selection dialog for easy connection
  • NEW Threshold monitoring with violation detection
  • NEW Device header preservation in CSV files

1.2 Key Features

  • Real-time Data Acquisition: Receives data from equipment at 0.1 to 1.0 second intervals
  • Automatic CSV Logging: Data saved with timestamp-based filenames, headers preserved
  • Three Live Plots: Forces, Travel measurements, and Loss of Stiffness monitoring
  • Threshold Monitoring: NEW Set limits for Upper Force and Loss of Stiffness
  • COM Port Detection: NEW Automatically finds available ports
  • Loss of Stiffness Calculation: Automatic calculation and visualization
  • Watchdog Timer: Alerts if no data received for 5 seconds
  • Mock Data Mode: Test without hardware
  • Unlimited Data Points: No artificial limits on test duration
  • Complete Test Traceability: Device ID and configuration preserved in every log

4. Connection & Port Detection

4.1 Automatic COM Port Detection NEW in V2.2

When you launch the application, it automatically detects all available COM ports and populates the dropdown list. No manual entry required!

How It Works:

  • Windows: Detects COM1 through COM16
  • Linux: Scans /dev/ttyUSB*, /dev/ttyACM*, /dev/ttyS*
  • macOS: Scans /dev/tty.* and /dev/cu.* patterns

If Auto-Detection Fails:

If no ports are detected, fallback list appears: COM1, COM2, ..., COM10. You can manually enter your port name.

4.2 Port Selection Dialog NEW in V2.2

Click the "🔋 Detect Ports" button to open the professional port selection dialog.

Port Selection Dialog Features:
  • Shows all detected ports with descriptions
  • Indicates availability (✓ Available)
  • Double-click a port to select it immediately
  • Or use Select button after choosing from list
  • Refresh button to re-scan for new ports

4.3 Serial Parameters

Baudrate Configuration

Default: 115200 (updated in V2.0)

Available Options: 4800, 9600, 19200, 38400, 57600, 115200

Important: The baudrate must match your fatigue testing equipment's settings. Mismatched baudrates cause parse errors or no data reception.

4.4 Connecting and Disconnecting

To Connect:

  1. Select COM port (from dropdown or "🔋 Detect Ports" dialog)
  2. Verify baudrate is correct
  3. Uncheck "Use Mock Data" if using real hardware
  4. Click Connect button
  5. Button changes to red and displays "Disconnect"
  6. Settings become grayed out
  7. Plots begin updating as data arrives

To Disconnect:

  1. Click the red Disconnect button
  2. Data reception stops
  3. Plots freeze at last received data
  4. Settings become available again

5. Data Logging

5.1 Automatic Logging

When you connect, the application automatically creates a new CSV file in the logs/ directory. Every data point received is logged immediately.

Filename Format:

fatigue_test_YYYYMMDD_HHMMSS.csv

Example:

fatigue_test_20260209_143215.csv

If File Exists:

Automatic counter appended to prevent overwriting:

  • fatigue_test_20260209_143215_01.csv
  • fatigue_test_20260209_143215_02.csv

5.2 CSV Format with Device Headers NEW in V2.2

CSV files now include device headers as comment lines at the top, preserving complete test metadata for traceability and reproducibility.

File Structure:

# ===== DEVICE HEADER INFORMATION =====
# ### VoiceCoilTestStand V1.5 ID=2BC4D630 ###
# For display ceSID-48339C75
# Loading... Adr: '1' (0x31). Ok!
# CNF;49;0;0;0;0;220;0;152;8;152;8;44;1;...;!
# ===== DATA BEGINS BELOW =====
Timestamp,Status,Cycles,Position_1_mm,Force_Lower_N,...
2026-02-09 14:30:22.145,DTA,11,0.78,2.9,...

Header Content Preserved:

  • Device ID: e.g., VoiceCoilTestStand V1.5 ID=2BC4D630
  • Display Info: e.g., ceSID-48339C75
  • Configuration: Complete CNF line with ~196 setup parameters
  • Status Messages: Loading and initialization messages

CSV Compatibility:

  • Excel: Opens normally, ignores comment lines
  • pandas: Use pd.read_csv(file, comment='#')
  • MATLAB: Use readtable(file, 'CommentStyle','#')
  • Most CSV tools: Automatically skip comment lines

5.3 Save Log with Custom Name

While Connected:

  1. Click "Save Log As..." button
  2. Choose location and filename
  3. Original log continues recording
  4. New file created as copy with your name

5.4 Start New Log File

During Test Operation:

  1. Click "Start New Log" button

  4. Data logging continues without interruption

6. Live Plotting

6.1 The Three Plots

Plot 1: Forces vs. Cycles

  • Blue line: Lower Force [N]
  • Red line: Upper Force [N]
  • Red circles: NEW Upper Force violations (if thresholds enabled)

Plot 2: Travel Measurements vs. Cycles

  • Green line: Travel at Upper Force [mm]
  • Cyan line: Additional Travel 1 [mm]
  • Magenta line: Additional Travel 2 [mm]

Plot 3: Loss of Stiffness vs. Cycles

  • Orange line: Loss of Stiffness [%]
  • Orange circles: NEW Stiffness violations (if thresholds enabled)
  • Calculation: (Travel_2 / Travel_at_Upper) × 100

6.2 Plot Controls

Update Interval

  • Default: 1000 ms (1 second)
  • Range: 100-5000 ms
  • Use Case: Increase for smoother viewing on slow systems

Auto Range

  • Enabled by default: Axes expand to show all data
  • When disabled: Manual panning/zooming possible
  • Typical Use: Keep enabled for automatic scaling

Clear Plots

  • Removes all displayed data from plots
  • Note: Does NOT affect logged CSV data
  • Useful to focus on recent data during long tests

6.3 Interpreting the Data

What the Plots Tell You:

Plot 1 (Forces): Shows how the testing machine is applying force. Look for:

  • Steady Upper Force indicates proper control
  • Increasing Lower Force might indicate wear
  • Sudden changes suggest equipment issues

Plot 2 (Travel): Shows positional movements. Look for:

  • Relatively stable values indicate normal operation
  • Increasing trends suggest material relaxation
  • Sudden jumps might indicate equipment slipping

    • Plot 3 (Loss of Stiffness): Indicates fatigue damage progression. Look for:

    • Zero or very low values in early cycles
    • Gradual increase shows material fatigue development
    • Steep increases might indicate approaching failure

    7. Threshold Monitoring NEW in V2.2

    7.1 What Are Thresholds?

    Thresholds are limits you set for Upper Force and Loss of Stiffness. The system automatically monitors data against these limits and shows you when values exceed them.

    7.2 Setting Upper Force Thresholds

    In the Plot Settings Panel:

    1. Find "Upper Force Thresholds" section
    2. Check the "Enable Thresholds" checkbox
    3. Spin boxes become active (no longer grayed out)
    4. Set "Upper Limit [N]" to your maximum acceptable force
    5. Set "Lower Limit [N]" to your minimum acceptable force
    6. Red dashed lines appear on Plot 1 showing the limits

    Default Values:

    • Upper Limit: 1000.0 N
    • Lower Limit: -1000.0 N
    • Step: 10.0 N

    Monitoring Violations:

    • When data exceeds limits: red circles appear on Plot 1
    • Statistics panel shows: "Upper Force Violations: X / Total"
    • Real-time update as violations occur

    7.3 Setting Loss of Stiffness Thresholds

    In the Plot Settings Panel:

    1. Find "Loss of Stiffness Thresholds" section
    2. Check the "Enable Thresholds" checkbox
    3. Spin boxes become active
    4. Set "Upper Limit [%]" to your maximum acceptable stiffness loss
    5. Set "Lower Limit [%]" to your minimum acceptable stiffness loss
    6. Orange dashed lines appear on Plot 3 showing the limits

    Default Values:

    • Upper Limit: 100.0 %
    • Lower Limit: 0.0 %
    • Step: 1.0 %

    Monitoring Violations:

    • When data exceeds limits: orange circles appear on Plot 3
    • Statistics panel shows: "Stiffness Violations: X / Total"
    • Real-time update as violations occur

    7.4 Changing Thresholds During Testing

    You can adjust threshold values while the test is running:

    • Changes take effect immediately
    • Lines and violation markers update instantly
    • Violation counters reset to 0
    • Previous data is re-evaluated against new limits
    • No data loss or interruption

    7.5 Disabling Thresholds

    To turn off threshold monitoring:

    • Uncheck the "Enable Thresholds" checkbox
    • Threshold lines disappear immediately
    • Violation markers cleared
    • Spin boxes grayed out
    • Violation counters reset to 0
    • Normal monitoring continues (no data loss)

    7.6 Threshold Monitoring Best Practices

    Tips for Effective Threshold Monitoring:
    • Start with wide limits: Set limits initially based on equipment specs
    • Tighten gradually: Narrow limits as you understand your test better
    • Monitor separate parameters: Upper Force and Stiffness are independent
    • Use for QA checks: Verify equipment is operating within acceptable ranges
    • Record violation times: Note when violations occurred for analysis
    • Adjust mid-test: Change limits if you discover you set them incorrectly

    8. Troubleshooting Guide

    8.1 Connection Issues

    Problem: "Failed to connect" error

    Diagnosis & Solutions:
    1. Port not found:
      • Try "🔋 Detect Ports" button to re-scan
      • Check in Windows Device Manager or Linux lsusb
      • Verify USB cable is firmly connected
    2. Wrong baudrate:
      • Verify in equipment manual (usually 115200)
      • Try common alternatives: 9600, 57600, 38400
      • Check equipment display/menu for settings
    3. Port in use:
      • Close any other applications using the port
      • Check Task Manager (Windows) for serial monitor programs
      • Restart application and try again
    4. Missing drivers (Windows):
      • Check Device Manager for unknown devices
      • Install drivers for your USB-to-Serial adapter (FTDI, Prolific, CH340)
    5. Linux permissions:
      • Run: sudo usermod -a -G dialout $USER
      • Log out and log back in
      • Or run application with: sudo python main_application.py

    Problem: Connection successful but no data

    Diagnosis & Solutions:
    1. Verify equipment is powered on and transmitting data
    2. Check cable connection (not just plugged in, but firmly seated)
    3. Try different baudrates (9600, 19200, 38400, 57600, 115200)
    4. Check equipment display/menu - may show "waiting" or "paused"
    5. Press any buttons on equipment to start test/transmission
    6. Consult equipment manual for communication settings

    8.2 Data Issues

    Problem: Parse errors in status log

    Common Causes & Solutions:
    1. Baudrate mismatch: Change baudrate to match equipment (usually 115200)
    2. Wrong COM port: Use "🔋 Detect Ports" to find correct port
    3. Electrical noise: Use shielded cables, keep away from power cables
    4. Cable problem: Try different USB cable or serial adapter
    5. Equipment firmware: Contact equipment manufacturer
    Note: Small numbers of parse errors (< 1%) are usually harmless and don't affect logging. The system filters header lines automatically in V2.1+.

    Problem: Watchdog timeout warnings

    Message: "No data received for 5 seconds!" What It Means: Application hasn't received data recently. This might be normal if:
    • Test completed and stopped transmitting
    • Brief communication pause
    • Equipment in standby/paused mode
    To Resolve:
    1. Check equipment display - is test running?
    2. Look at statistics panel - has "Lines Received" counter increased?
    3. Verify cable connections
    4. Check equipment for error messages
    5. Try disconnecting and reconnecting

    8.3 Plotting Issues

    Problem: Plots not updating

    Checklist:
    1. Verify "Connected" button status in status bar
    2. Check "Lines Received" counter is increasing
    3. Check "Points Plotted" counter is increasing
    4. Verify "Auto Range" is enabled
    5. Try "Clear Plots" button - watch for new data
    6. Disconnect and reconnect
    7. Check for parsing errors in status log

    Problem: Plots appear laggy

    Solutions:
    1. Increase Update Interval to 2000-3000 ms
    2. Close other resource-intensive applications
    3. Use "Clear Plots" to reduce data on screen
    4. If test running many hours, consider starting new log

    8.4 Data Logging Issues

    Problem: Cannot find log files

    Solutions:
    1. Default location: logs/ subdirectory in application folder
    2. Check filename shown in "Data Logging" section
    3. Look for files matching pattern: fatigue_test_*.csv
    4. In Windows Explorer, search for *.csv files
    5. Enable "Show Hidden Files" if logs folder not visible

    Problem: CSV file empty or incomplete

    Causes & Solutions:
    1. Test just started - wait for data to accumulate
    2. Check "Points Logged" in statistics - if 0, no data parsed
    3. Check status log for parse errors
    4. Verify equipment is actually sending data
    5. Try with mock data to test CSV functionality

    9. Frequently Asked Questions

    Q: What baudrate should I use?

    A: Default is 115200 (updated in V2.0). If you have issues, try these in order: 57600, 38400, 19200, 9600. Check your equipment's manual or display settings.

    Q: Why am I getting parse errors?

    A: Usually indicates baudrate mismatch. Verify your equipment's baudrate setting. Small numbers of parse errors are normal. The system filters header lines automatically.

    Q: How long can a test run?

    A: No time limit! Version 2.2 supports unlimited data points. However, very long tests (days) might slow down plotting.

    Q: Can negative forces be logged?

    A: Yes! Version 2.0+ fully supports negative values for force and position. They're plotted and logged normally.

    Q: What is "Loss of Stiffness"?

    A: It's calculated as: (Additional Travel 2 / Travel at Upper Force) × 100%. It indicates material fatigue. Increasing values mean the material is getting softer.

    Q: Where are my CSV files saved?

    A: In the logs/ subdirectory inside the application folder. Filenames are: fatigue_test_YYYYMMDD_HHMMSS.csv

    Q: Can I recover data if I close without saving?

    A: Yes! The application automatically saves to CSV every single data point. Just look in the logs/ directory for your file.

    Q: What's in the header comments in my CSV file?

    A: Device identification (serial number), display module ID, equipment configuration, and status messages. This preserves complete test metadata for reproducibility.

    Q: How do I use thresholds?

    A: Check the "Enable Thresholds" checkbox in Plot Settings, set your limit values, and the system will mark violations with colored circles and count them in Statistics.

    Q: Can I change thresholds while testing?

    A: Absolutely! Change thresholds at any time - they take effect immediately with no data loss.

    Q: What if the "Detect Ports" button doesn't find my port?

    A: You can manually type your port name in the dropdown box, or check Device Manager (Windows) / lsusb (Linux) to find it.

    10. Advanced Features

    10.1 Statistics Monitoring

    The Statistics panel shows real-time operation metrics:

    Statistic Meaning Notes
    Connection Time Elapsed seconds since connection Tells you how long test has been running
    Lines Received Total raw lines from serial port Includes headers, config, data, all types
    Points Logged Successfully parsed and logged data points Should match your expected cycles
    Points Plotted Data points currently shown on plots Same as logged unless Clear Plots used
    Buffer Size Number of data points in memory Shows how much data is buffered
    Parse Errors Invalid lines that couldn't be parsed A few errors are normal; many indicate problems
    Upper Force Violations Data points exceeding Upper Force limits Only shown if thresholds enabled
    Stiffness Violations Data points exceeding Stiffness limits Only shown if thresholds enabled

    10.2 Loss of Stiffness Formula

    If you want to manually verify calculations:

    Loss_of_Stiffness [%] = (Travel_2 / Travel_at_Upper) × 100

Where:
  Travel_2 = Additional travel to reach Upper Force [mm]
  Travel_at_Upper = Total travel at Upper Force [mm]
  
Special case: If Travel_at_Upper = 0, returns 0%
